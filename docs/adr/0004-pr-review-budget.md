# Бюджет запусков агента по `/oc`

Команда `/oc` в комментарии к PR запускает агента, который может менять код и
открывать коммиты. Без ограничения цикл «замечание → правка → повторный
запуск» может длиться сколько угодно и незаметно расходовать модель. Нужен
предсказуемый предел и честный итог, когда он исчерпан.

## Решение

Бюджет — **2 попытки на один PR/issue**. Попытка считается по истории
Actions, а не по комментариям:

- каждый прогон workflow `opencode` получает `run-name`
  `opencode budget v1 #<PR> · <comment-id>`;
- бюджета считает сумму `run_attempt` по прогонам этого workflow, у которых
  тот же номер PR/issue и `conclusion != "skipped"`;
- `run_attempt` увеличивается при Re-run, поэтому повторный запуск тоже
  расходует попытку; отменённый прогон остаётся в истории и тоже считается;
- прогоны без команды `/oc` завершаются `skipped` (джоба не запускается) и в
  счёт не идут;
- текущий прогон уже виден в списке, поэтому его попытка входит в сумму:
  при бюджете 2 третий запуск видит 3 и отказывает.

Проверка стоит **до** вызова модели, поэтому исчерпанный бюджет не тратит
токены. Права джобы для этого: `actions: read`.

## Итоги прогона

Итог публикует отдельный шаг без модели — по исходам шагов и прошедшему
времени. В комментарии всегда есть причина, последний известный SHA, ссылка
на логи и явный статус.

| Причина | Поведение | Прогон |
| --- | --- | --- |
| `limit_exhausted` | комментарий, лейбл `ready-for-human` | зелёный: отказ — ожидаемое решение |
| `timeout` | комментарий, лейбл `ready-for-human` | красный |
| `infra` | комментарий, лейбл `ready-for-human` | красный |
| `agent_failed` | комментарий, лейбл `ready-for-human` | красный |

`timeout` определяется по шагу с `timeout-minutes` и прошедшему времени:
composite-экшен `anomalyco/opencode/github` не имеет собственного тайм-аута и
не отдаёт его наружу.

## Consequences

- Формат `run-name` — часть контракта: его изменение ломает подсчёт, поэтому
  версия `v1` вынесена в префикс.
- Бюджет — процессное ограничение, а не защита от злоупотребления: владелец
  репозитория может отключить workflow или изменить число. Это осознанно:
  решение о мерже всё равно за человеком.
- Лейбл `ready-for-human` снимается вручную после разбора; автоматически он
  не снимается, чтобы не потерять сигнал.
- `limit_exhausted` не перезапускает модель и не чинит код: дальнейшие
  действия — решение человека.
