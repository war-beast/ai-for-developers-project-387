# Обращения от локального агента не проходят автотриаж

GitHub не различает, где создан issue: `gh issue create` из локального клона
и форма в веб-интерфейсе дают одно и то же событие `issues: opened` от одного
и того же аккаунта. Поэтому «создано локальным агентом» нельзя вывести из
автора — нужен явный маркер, который агент ставит сам.

Обращения, написанные локальным агентом вместе с владельцем, уже согласованы:
им не нужен цикл «разбор → вопросы → спека → тикеты», они предназначены для
реализации человеком. Автотриаж тратит на них прогон модели и переписывает
готовое обращение в `needs-info` и `ready-for-agent`, что меняет смысл задачи.

## Решение

- Лейбл **`no-triage`** — служебный маркер «создано локально, разбирать не
  надо»; он не входит в канонические роли из `docs/agents/triage-labels.md`.
  Отдельный лейбл, а не `ready-for-human`: тот выражает состояние разбора
  («нужен человек») и ставится автоматикой бюджета `/oc`, поэтому совмещать в
  нём два смысла нельзя.
- Локальный агент создаёт issue только через `mise run issue-create` — обёртку
  над `gh issue create --label no-triage`. Лейбл ставится в том же запросе
  создания, поэтому попадает в payload события `issues: opened`.
- Workflow `opencode-triage` проверяет лейбл дважды: в `if:` джобы по payload
  и отдельным шагом до вызова модели по API. Второй проверки достаточно, если
  лейбл добавили вторым вызовом API и payload его не содержит.
- Триаж, сам создающий issue (спека, тикеты), работает под ботом, поэтому
  лейбла не получает и в фильтр не попадает.

## Последствия

- Пока лейбл `no-triage` стоит, разбор не запускается ни по `opened`, ни по
  `issue_comment`: проверка лейбла стоит в `if:` джобы, поэтому действует на
  оба события. Ручная пометка `needs-info` сама по себе разбор не включает.
- `needs-info` на такое issue триаж не ставит — это следствие, а не условие
  гарантии.
- Вернуть разбор вручную: снять `no-triage`, поставить `needs-info` и
  написать комментарий. Только снятия лейбла мало — триггер `opened` уже
  прошёл, а продолжение требует `needs-info`.
- Сырой `gh issue create` без лейбла продолжает запускать автотриаж — это
  поведение для обращений, которым нужен разбор.
- Лейбл живёт в репозитории, а не в клоне: джоба `Ensure triage labels`
  пересоздаёт его при необходимости.
